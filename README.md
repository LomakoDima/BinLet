# Binlet

A tiny Windows 11 tray utility that puts the native Recycle Bin in the notification area.

- Tray icon with distinct **empty / full** states and a tooltip (`Binlet — Recycle Bin empty`, `Binlet — Recycle Bin contains 12 items`).
- **Left-click** opens the native Recycle Bin (File Explorer, `shell:RecycleBinFolder`).
- **Right-click** menu: *Open Recycle Bin*, *Empty Recycle Bin*, *Start with Windows* (checkable), *Exit*.
- *Empty Recycle Bin* always asks first (default button is Cancel), then calls the Shell's own `SHEmptyRecycleBin`. Binlet has no deletion logic of its own and never touches Recycle Bin files.
- Only one instance runs per user session; a second launch exits silently.

Everything else (file browsing, history, statistics, settings pages) is intentionally out of scope.

## Download

Grab `Binlet-vX.Y.Z-win-x64.zip` from the repository's **Releases** page and unzip `BinLet.exe` anywhere. No installer and no .NET install needed. The exe is not code-signed, so SmartScreen may warn on first run.

## Prerequisites

- Windows 11 x64
- [.NET 10 SDK](https://dotnet.microsoft.com/download) to build (not needed to run the published exe, which is self-contained)

## Build and run

```powershell
dotnet build BinLet.slnx -c Debug
dotnet run --project BinLet/BinLet.csproj
```

## Publish (single self-contained exe)

```powershell
dotnet publish BinLet/BinLet.csproj -c Release -r win-x64 --self-contained true -p:PublishSingleFile=true
```

Output: `BinLet/bin/Release/net10.0-windows10.0.22000.0/win-x64/publish/BinLet.exe` (~173 MB, because it bundles the .NET runtime, WPF and Windows Forms). Single-file compression was tried and rejected: it cut the size to ~76 MB but raised the running process's private memory from ~18 MB to ~93 MB, which is the wrong trade for an always-on tray app.

The icons in `BinLet/Assets` are generated by `tools/make-icons.ps1` (run it to regenerate).

## Releasing

CI (`.github/workflows/ci.yml`) builds every push to `main` and every pull request. Pushing a tag creates a release with the zipped exe attached (`.github/workflows/release.yml`); the tag becomes the file version:

```powershell
git tag v1.0.0
git push origin v1.0.0
```

Keep `<Version>` in `BinLet/BinLet.csproj` in step with the tag for local builds. The workflows have not been run yet, so check the first run in the Actions tab.

## How it works

| Concern | Implementation |
| --- | --- |
| Bin state, all drives | `SHQueryRecycleBin` with a null root path (aggregates every drive), run off the UI thread |
| Live updates | `SHChangeNotifyRegister` on the Recycle Bin folder, received by a message-only window, debounced (300 ms); plus a 60 s fallback refresh |
| Empty | Confirmation (native `TaskDialog`) → `SHEmptyRecycleBin(..., SHERB_NOCONFIRMATION)` on a dedicated STA thread; the Shell shows its own progress UI. "Already empty", user-cancel, and failure HRESULTs are handled; no success is claimed on failure |
| Startup | `HKCU\Software\Microsoft\Windows\CurrentVersion\Run` value `Binlet` (no admin). Also honours/clears Task Manager's per-user `StartupApproved\Run` entry for that same value name. Reported as enabled only if the entry points at the running exe |
| Single instance | Named mutex in the `Local\` namespace |
| Menu | WPF `ContextMenu` using the Windows 11 Fluent theme (`ThemeMode="System"`, follows light/dark) |
| Settings | None stored; the registry entry is the only persisted state |

Source layout (`BinLet/`): `App.xaml(.cs)` lifecycle and single instance · `TrayController.cs` icon, menu, actions · `RecycleBinShell.cs` / `RecycleBinWatcher.cs` / `NativeMethods.cs` Shell integration · `StartupRegistration.cs` · `Dialogs.cs`.

## Verification status

Checked programmatically on Windows 11 (Debug and published Release exe):

- Build: 0 errors, 0 warnings. Single-file publish succeeds.
- Published exe starts, stays running, idles at ~18 MB private memory; a second launch exits and leaves one process.
- `SHQueryRecycleBin` result matches the Shell's own item count (this caught a struct-layout bug that is now fixed).
- Change notifications: recycling a temp file triggers the watcher in ~0.4 s, and restoring it triggers it again; the watcher disposes cleanly.
- Startup: enable / disable / repeat each / read-back all behave, and the Run entry points at the exe path. The entry was removed again afterwards.
- Icon resources load from the assembly (empty and full), with a fallback to a system icon if they are missing.
- `SHEmptyRecycleBin` P/Invoke signature was called against a non-existent drive only; it returns an error HRESULT without crashing.

**Not verified (needs a human, no UI automation was run):**

1. The tray icon actually appears, and its icon/tooltip switch between empty and full when you delete a file and when you empty the bin. (New icons may sit in the "hidden icons" overflow; drag it to the visible tray.)
2. Left-click opens Explorer's Recycle Bin once (double-click should not open two windows).
3. Right-click shows the menu, it closes when you click elsewhere or press Esc, and it flips above/beside the taskbar correctly. This is the least certain piece: popups from a tray icon are fiddly and Binlet works around it by activating the popup window.
4. *Empty Recycle Bin* with items: the confirmation shows the item count and size; Cancel leaves everything untouched; confirming empties the bin and the icon switches to empty. With an empty bin, a balloon says it is already empty.
5. *Start with Windows*: tick it, check Task Manager → Startup apps shows Binlet, sign out/in and confirm it starts; untick and confirm it is gone.
6. *Exit* removes the icon immediately and the process ends (`BinLet.exe` gone from Task Manager).
7. Behaviour on high-DPI and multi-monitor setups, and with the taskbar on a different edge.

The real empty operation was not run against your Recycle Bin.

## Limitations

- Windows 11 x64 only (targets `net10.0-windows10.0.22000.0`).
- The Fluent theme for WPF is still marked experimental in .NET 10; the build suppresses warning `WPF0001` for it.
- The confirmation dialog is the system task dialog and does not follow dark mode.
- Binlet cannot place anything on the taskbar itself; it is a tray utility only.
- If the exe is moved after enabling *Start with Windows*, the menu shows the option unchecked until you tick it again for the new location.
